# room_memory: plan (Phase 2, PR 2.1 / 2.2, offline)

Scope: research brief §2.2 steps 1, 3, 4, 5 and the persistence half of 7, and §3 Phase 2 rows PR 2.1 and PR 2.2, as far as they can be built and tested on the Mac without ROS or the Spark. Contracts: `docs/CHANGE-DETECTION.md` (v2, the parity spec) and `docs/ROOM-MEMORY-PROTOCOL.md` plus `ros/labcommand_msgs/` on the Phase 0 branch (`labcommand-memory`). This branch follows the revised Phase 0 decisions: `compression` sits in the header before one `uint8[] payload` (zlib = raw DEFLATE by default), `RequestSync` exists, and all-free bricks are sent.

## Parity rules (the port reproduces the Swift bytes)

- Every value the spec calls binary32 is a `numpy.float32` scalar or array: `inverse = f32(1) / voxel_size`, the quantizer product, range test `(x*x + y*y) + z*z`, AABB and volume products, the DDA (`dir`, `tDelta`, `tMax`, accumulated `tMax += tDelta`), centroid distance with `np.sqrt`, count ratio. Centroids are binary64 `((sum / n) + 0.5) * size` rounded once to binary32. Bits are written with `.view(uint32)`.
- Floor is the spec's truncate-and-adjust on binary32 `q` inside the `|q| < 2^20` guard.
- Occupied sets are sorted unique `int64` key arrays; membership is `searchsorted`. No hash order reaches any output.
- Representative ray endpoint: one argsort on the voxel key, then segmented minima (`minimum.reduceat`) of the x order key, of y among the x ties, of z among the y ties; order keys invert exactly to the binary32 coordinates.
- DDA: all rays walk in lockstep as numpy arrays (iteration counter = `steps`, since every ray starts together), with the spec's order: `tMax < 0 → 0`, then the NaN check, `current == end` before marking, cap `|di|+|dj|+|dk|`, then the per-axis clamp (an axis on its endpoint index gets `tMax = +inf`), and ties step every tied axis still short of its end. The clamp keeps each axis between its start and end index, so every visited cell is inside the origin–end box and packs; the spec's box skip and pack-failure exit never fire and are not coded. Marks are packed keys; for the map layers all marks are kept. For the diff only marks on the before-only candidates matter, so (exactly, because every axis steps monotonically toward its end) a ray is dropped once it has left the candidates' index box in its step direction, and membership is a dense boolean grid over that box when it holds ≤ 2²⁵ cells, else a binary search. No dense grid over the whole ray AABB (JT128 ranges make it too large).
- Clusters: breadth-first walk over a Python set of keys; geometry from exact integer index sums, so visit order cannot matter. A component drops under `min_voxels` voxels or under `min_extent` cells on any axis of its index box (default 2; the snapshot goldens are `regions` empty because of it).

## Memory model (PR 2.2)

- A `VoxelLayer` is two sorted key arrays, `occupied ⊆ known`; free = known − occupied; everything else is UNKNOWN.
- One window: occupancy of the accumulated points (`maxRange` clip), free = every cell an after-ray marks (the spec DDA from the sensor origin), occupied wins.
- Per sensor until the JT128↔Mid-360 extrinsic exists (brief R1): Mid-360 = `/livox/lidar`, `per_sensor_hz[0]`, sensor bit 0; JT128 = `/lidar_points`, `[1]`, bit 1. Points stay in each sensor's frame, origin (0, 0, 0).
- Reference layer: the settled part of per-voxel window counts (`VoxelStats`: windows that observed a voxel, windows that hit it) over the first `reference_windows` (30) windows per configured sensor. Occupied: at least `occupied_min_hits` (2) hits and a hit share of at least `occupied_min_ratio` (0.3). Free: seen at least `free_min_seen` (2) times with a hit share of at most `free_max_ratio` (0). Everything else stays UNKNOWN. When every configured sensor has its windows, state BUILDING → TRACKING, `map_epoch` 0 → 1, references saved. In TRACKING the unsettled voxels keep counting, unless the window's pose estimate exceeds `learn_max_offset_m`. Voxels that settle join the reference at the next map tick (new coverage), and settled voxels are never revised. Recent layer: the last `recent_windows` (3) windows. The thresholds come from the static recording (`spark/room_memory_cpp/PLAN.md`, "False change events"). Change = core `diff(reference.occupied, recent)` with evidence on, so a reference voxel the recent rays do not traverse is UNKNOWN, not DISAPPEARED; and with `before_known = reference.known` (an engine-only extension, off in the offline CLI and the goldens), so a recent voxel the reference never observed is new coverage, not APPEARED. Both kinds therefore need evidence in both layers (protocol §4.2). A region with a voxel center within `near_range_m` (2.0 m) of the sensor, either pose of a move, is not reported (protocol D27); the engine's diff runs with `tolerance` 2 and `min_voxels` 8 (the core defaults stay 1 and 6).
- Save/load: one `MapBricks` snapshot (zlib) per sensor, `<state_dir>/<room_id>/reference-<sensor>.cdr`, written atomically. It carries `room_id`, `map_epoch`, `voxel_size` and the bricks, so reload restores identical bricks. Every save also writes `<state_dir>/<room_id>/map_epoch` (decimal and a newline), the room's last epoch whichever sensors ran; a reload takes one past the highest of it and the loaded references, so sync cursors never repeat across restarts or sensor subsets. Bricks: `floor(v / 8)`, bit `x + 8y + 64z`, canonical `(i, j, k)` order, all-free bricks kept, all-unknown omitted.

## Node behaviour, and what is deliberately not here

- State: BUILDING, TRACKING, DEGRADED (a configured sensor measured 0 Hz, or the last window was dropped). RIG_MOVED and PAUSED are never emitted: acting on the rig-pose estimate, and operator actions, are PR 2.3 / 3.1. Loading a saved reference goes straight to TRACKING.
- Status: `n_bricks` and `coverage_known_frac` describe the published map, the `map_sensor`'s reference. Coverage is its known voxels inside the index box of its occupied voxels, divided by the box's voxel count. `pose_residual_m` is `pose_offset`: the norm of the per-axis shifts (−4 … +4 voxels, parabola-refined) that best register the latest window onto the reference, the largest over sensors, NaN while BUILDING (protocol §3.3).
- Events: one message per transition only. A region must match in `candidate_windows` (3) fresh windows without a break before its CANDIDATE is sent (fresh: the window itself occupies an appeared or moved region's voxels, or its own rays traverse a disappeared region's; a return or free space kept in the recent layer does not count again; an open MOVED is kept alive by its own APPEARED and DISAPPEARED halves seen in the same window, not by either alone); an open candidate goes EXPIRED after `expire_windows` (3) windows without a match. CONFIRMED is never sent: T_commit and moved supersession are PR 2.3. `alpha` is NaN; `evidence` is the share of region voxels known in both layers (1.0 by construction now that both kinds require it); the mask holds the region's voxels (zlib). `event_id` starts at `node_start_unix_ms << 20`, unique per room across restarts while the Spark clock does not step back.
- Map stream: `map_update` after each window gives the live `MapBricks`. That is a snapshot when TRACKING starts and every `keyframe_period_s` (60 s), and in between a delta of the changed bricks at most every `delta_period_s` (5 s), only when voxels settled. A snapshot replaces a delta once the deltas since the last snapshot would exceed `keyframe_delta_ratio` (0.5) of its size. `sync` answers `RequestSync` by protocol §5 from logs of the last 10 map and 100 event messages. The node publishes both on the protocol's topics. `Epoch` is not published.
- Not built or run here: `docker build` (pulls `ros:jazzy`, which is network beyond pip), `colcon build`, any Spark contact. The container build needs `ros/labcommand_msgs` from the Phase 0 branch in the build context. The production node is `spark/room_memory_cpp`, whose launch file also starts the read-only foxglove_bridge on :8767. This package is its byte-exact oracle.

## Deviations from the Swift side

- LZFSE: Python's standard library has none. The decoder reads LZFSE streams made of uncompressed blocks (`bvx-`, which is what `map_bricks_delta_lzfse_le.hex` holds) and raises *unsupported* for compressed LZFSE blocks; the encoder writes NONE or ZLIB only (the Spark sends zlib, protocol §3.1).
- The Python inflaters also reject bytes after the end of a compressed stream; Apple's does not detect them (protocol §3.1 notes the same asymmetry).
- The offline CLI reads `.bin` (CDR PointCloud2) only, not `.pcd`.
